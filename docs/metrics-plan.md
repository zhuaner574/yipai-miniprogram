# MVP 数据验证方案

“一拍一拍”的第一阶段不以注册人数为唯一成功标准，而是验证用户是否愿意持续记录，以及赛后回应是否真正有帮助。

## 核心漏斗

1. 完成新用户引导：`onboarding_completed`
2. 创建第一条记录：`session_created`
3. 看到赛后回应：保存成功页自动展示
4. 对回应评价：`reply_rated`
5. 7天内创建第二条记录：由 `session_created` 时间计算
6. 主动提交产品反馈：`feedback_submitted`

## 首轮建议观察指标

| 指标 | 计算方式 | MVP参考目标 |
|---|---|---:|
| 首次记录转化率 | 完成引导后24小时内创建记录人数 / 完成引导人数 | ≥ 60% |
| 记录完成时间 | 进入记录页到保存成功的中位时长 | ≤ 90秒 |
| 回应有用率 | 选择“有一点”的次数 / 全部回应评价次数 | ≥ 60% |
| 7日二次记录率 | 首次记录后7天内再次记录人数 / 首次记录人数 | ≥ 30% |
| 日记填写率 | 日记非空记录数 / 全部记录数 | 观察值，不设硬目标 |
| 主动反馈率 | 提交反馈人数 / 活跃体验人数 | ≥ 15% |

## 首轮访谈问题

- 你在什么时刻想到打开“一拍一拍”？
- 哪一步让你觉得记录太麻烦？
- 看到赛后回应时，你觉得它懂网球吗？
- 哪句话让你感觉像模板？
- 如果只能保留一个页面，你会保留哪个？
- 什么情况下你愿意连续使用一个月？

## 迭代判断

- 首次记录低：缩短表单、允许只填类型和时长。
- 回应有用率低：按场景重写回复库，不急于增加大模型自由生成。
- 二次记录率低：优化首页回顾、训练间隔提醒和月度目标。
- 日记填写率低但留存正常：日记不是必要输入，不强迫用户填写。
- 用户频繁要求预算或球场：再将对应功能进入下一版本。
