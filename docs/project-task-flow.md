# 《一拍一拍》项目任务流

## 1 文档目的

这份文档用于回答三个问题：

1. 项目从旧电脑恢复后经历了哪些阶段
2. 每个阶段解决了什么问题并形成了什么产出
3. 当前处于哪里 下一步如何继续推进

## 2 项目总览

```text
旧项目恢复
  → 产品上下文重建
  → 高保真 UI 回顾
  → 文案与视觉精修
  → 小程序工程恢复
  → 微信账号与云开发接入
  → 核心功能补全
  → 情绪回应体系重构
  → 品牌形象统一
  → 云端数据与隐私能力完善
  → 自动化与真机验收
  → 体验版测试
  → 隐私整改与备案审核
  → 代码审核与正式发布
```

## 3 分阶段任务流

### 阶段 0 旧电脑资料恢复与上下文重建

目标：从“旧电脑备份”和上一台 Windows 电脑留下的 Codex 项目资料中恢复项目，重新建立对“校招”和“一拍一拍”的完整理解。

完成事项：

- 定位并恢复 `yipai-miniprogram` 项目目录
- 阅读项目说明 页面结构 配置 文档 测试和历史预览
- 恢复“一拍一拍”的产品定位 用户场景和未完成功能
- 将项目从静态预览状态重新带回可继续开发状态

阶段产出：

- 可运行的小程序工程
- 项目文档与代码上下文
- 后续 UI 和功能迭代基础

### 阶段 1 最新 UI 回顾与布局修复

目标：先用一套完整 UI 帮助快速回忆产品全貌，再逐页修复明显问题。

完成事项：

- 恢复并打开高保真预览页面
- 修复首页月历 卡片 导航栏和浮动按钮错位
- 调整数值与单位的对齐和间距
- 让首页完整展示六周日历
- 将“记录这一拍”从遮挡内容的悬浮形态改为页面流内入口
- 统一标题断行 去除不必要标点
- 检查小屏 大屏和 Android 模拟器布局

关键决策：

- 视觉风格采用米白 深网球绿和荧光网球黄
- 大标题短句化 标题尽量通过换行而非标点制造节奏
- 核心 CTA 必须醒目但不能遮挡内容

### 阶段 2 文案去 AI 化与产品语气建立

目标：把空泛 冗长和“像 AI 写的”文案改成简洁 自然 有情绪价值的产品语言。

完成事项：

- 欢迎页和引导页改用短句
- 删除过度解释产品理念的长文案
- 保留“拍拍可以拍拍你”的亲切表达 不展开解释命名缘由
- 删除“懂你的进步 也懂你的不容易”等空泛口号
- 调整页面辅助文案和提示文案的标点 空格 换行与语序
- 将反馈页预设改进标签改为自由填写建议

形成的文案原则：

- 页面标题短而明确
- 不为了精简牺牲信息和情绪价值
- 不使用宏大判断和过度承诺
- 不把小挫折上升为“否定努力”或“不适合网球”
- 正向情绪只给正向反馈 不擅自引入失落

### 阶段 3 微信小程序账号和开发环境接入

目标：从静态项目进入真实微信小程序开发与测试环境。

完成事项：

- 注册小程序账号和独立邮箱
- 完成小程序基础信息与头像准备
- 获取并配置 AppID
- 下载并安装微信开发者工具
- 导入 `yipai-miniprogram` 项目
- 选择微信云开发作为后端
- 创建云开发环境 `cloud1`
- 配置环境 ID
- 部署 `login` 云函数
- 开启微信开发者工具服务端口
- 建立 CLI 与自动化测试连接

阶段产出：

- 正式 AppID 项目
- 微信开发者工具可编译工程
- 微信云开发环境
- 可进行模拟器 真机和体验版测试的基础设施

### 阶段 4 首次引导与网球画像重构

目标：让用户先理解产品，再用低压力方式完成必要资料，而不是打开后立即填写昵称。

完成事项：

- 新增欢迎介绍页
- 明确产品是网球记录工具
- 用“网球搭子 拍拍”体现陪伴定位
- 设计昵称 水平 球龄 小目标和回应风格流程
- 水平选项调整为 `1.0` `1.5` `2.0` `2.5` `3.0` `3.5+`
- 球龄调整为细分时间段
- 小目标改为多选并支持“其他”输入
- 新增持拍手 打球原因 练习方式 频率 球友 比赛经历和困扰画像
- 多个画像题改为多选
- 画像支持跳过 修改和完整回填
- “我的小目标”的修改入口直接回到目标编辑页
- 删除两个不再需要的坚持和提醒问题

关键决策：

- 必填信息保持最少
- 画像是为了后续理解用户 不是为了制造注册门槛
- 所有画像都允许后续修改

### 阶段 5 打球记录主流程完善

目标：让用户在一次上场后用较低成本留下完整记录。

完成事项：

- 支持拉球 学球 发球机和比赛四类记录
- 支持自由选择日期 开始时间和持续时长
- 支持补记历史日期并自动带入日期
- 支持修改和删除单条记录
- 支持心情选择 困扰多选和其他补充
- 支持选填日记
- 修复编辑记录时困扰无法重新选择的问题
- 断网保存失败时保留填写内容并允许重试

关键决策：

- 日记永远选填
- 困扰关键词用于帮助回应理解情境 不用于给用户贴标签
- 普通记录尽量在 60 至 90 秒内完成

### 阶段 6 比赛记录扩展

目标：覆盖业余爱好者从单轮约球到多轮业余赛事的真实记录场景，同时不让主表单过于复杂。

完成事项：

- “单场比赛”统一为“单轮比赛”
- “连续赛事”统一为“多轮比赛”
- 比赛详情从主记录页拆到独立选填页面
- 比赛级别加入 `2.0`
- 支持级别 胜负 比分
- 多轮比赛支持场次数 胜负数和最终名次
- 支持八强 四强 亚军 冠军和具体名次等结果
- 在个人页按级别展示胜负数量和胜率

关键决策：

- 比赛结果是选填项
- 先完成打球记录 再按需补充赛事细节
- 单轮与多轮采用不同数据结构和展示逻辑

### 阶段 7 日历 成长和记录管理

目标：让用户看见持续积累，并能可靠地回看 修改 删除和补记。

完成事项：

- 首页展示本月次数 时长 打球日和当前阶段
- 完整月历展示上月 下月和当月日期
- 浅绿色标记打球日
- 灰色圆圈默认标记今天
- 今天使用“记录今天” 历史日期使用“补记这一拍”
- 点击历史日期查看当日记录
- 从历史日期进入记录页时自动回填日期
- 成长页按时间倒序展示记录
- 每条记录展示对应拍拍情绪形象
- 支持修改 删除 收起和展开

### 阶段 8 成长勋章体系设计

目标：将成长反馈分为长期积累和月度行动，既保留里程碑，也给用户每月重新开始的机会。

完成事项：

- 长期成就：第一次 累计次数 累计时长 比赛 日记 打法和隐藏成就
- 本月挑战：上场次数 时长 日记 打法 比赛和打球天数
- 长期成就点亮后永久保留
- 月度挑战按自然月重新计算
- 首页仅展示 6 个长期成就和 4 个月度挑战
- 新增“更多”进入完整勋章页
- 已点亮优先 最近点亮优先
- 未点亮按完成百分比和剩余距离排序
- 新勋章解锁时显示庆祝弹层和轻量特效

### 阶段 9 情绪回应语料库重构

目标：从泛化安慰升级为理解网球具体情境的回应系统。

完成事项：

- 建立开心 有进步 平静 有点累 沮丧五类心情回应
- 针对关键分 输球 被翻盘 紧张 发球 失误 手感 瓶颈 改动作 教练反馈 强对手 比较和身体疼痛建立场景库
- 困扰改为多选并支持其他
- 三种语气：温柔陪伴 刚刚好 直接一点
- 根据心情 困扰 日记关键词和语气路由回应
- 同类心情连续记录时轮换话术
- 语料逐句编号并完成多轮人工审核
- 删除极端负面 空泛和“钢铁直男”表达
- 平静回应不评价过程是否顺利 只承认完成和坚持
- 正向情绪不引入失落 比较或否定判断
- 建议只给一个小而具体的下一步
- 用户可反馈回应是否接住自己

关键决策：

- 当前采用受控语料库而非开放式大模型生成
- 网球具体性优先于泛化情绪价值
- 情绪价值不是夸奖 而是准确理解和不过度解读

### 阶段 10 “拍拍”品牌形象统一

目标：让“拍拍”从装饰图变成可识别的网球陪伴角色。

完成事项：

- 重新设计网球拟人形象
- 统一头带 球拍 鞋子和品牌配色
- 制作小程序头像和封面图
- 去除头像复杂背景 保留主体
- 修复圆形头像和卡片头像的视觉偏移
- 制作开心 有进步 平静 疲惫 沮丧五种情绪形象
- 在欢迎页 回应页 成长记录和勋章庆祝中统一使用

### 阶段 11 云端 数据安全和可恢复版本

目标：从本地演示升级到真实账号数据同步，并确保项目与用户数据都可恢复 可删除 可隔离。

完成事项：

- 建立 Git 基线分支 `codex/yipai-baseline-20260802`
- 建立连续可恢复提交和 `yipai-v0.1.0-rc1` 标签
- 创建 `profiles` `sessions` `feedback` `events` 四个集合
- 四个集合设为仅创建者可读写
- 部署 `deleteAccountData` 云函数
- 仅根据云端 `OPENID` 删除当前账号数据
- 新增“删除我的全部数据”并二次确认
- 新增小程序内“数据与隐私说明”

### 阶段 12 自动化 真机和云端验收

完成事项：

- JavaScript 语法 JSON 页面结构和资源检查
- 核心数据 增删改查 月历 勋章 比赛统计和回复匹配测试
- 模拟器覆盖完整引导 记录 修改 删除 补记 比赛 画像和统计
- 真机验证云端新增 读取 修改 删除和持久化
- 换微信账号验证数据隔离
- 第二账号验证删除全部数据不影响主账号
- 验证 `feedback` 云端写入
- 验证断网保留内容和重试
- 验证小屏 大屏和 Android 模拟器适配

### 阶段 13 发布与合规推进

完成事项：

- 完成小程序基础信息 服务类目和封面头像
- 提交小程序备案 当前审核中
- 首次隐私保护指引因自定义信息与接口检测不匹配被退回
- 调整为接口声明与小程序内业务数据说明分离
- 准备体验版与首批球友测试

## 5 后续标准迭代流程

```text
提出修改
  → 明确影响页面和数据
  → 修改代码与文档
  → 自动化测试
  → Git 提交形成恢复点
  → 开发者工具编译
  → 模拟器和真机预览
  → 上传新版本
  → 设置体验版
  → 体验反馈
  → 提交审核
  → 发布
```

若修改涉及新增手机号 位置 相册 摄像头等隐私接口，需要同步更新隐私保护指引。若修改涉及主体 服务性质或经营范围的实质变化，需要评估备案和服务类目是否变更。
